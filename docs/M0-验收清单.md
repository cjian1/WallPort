# M0 桌面底座：验收清单

M0 只回答一个问题：**桌面层窗口在 macOS 的各种交互下能不能稳定地待在"系统壁纸之上、桌面图标之下"。**

应用每次遇到相关事件（启动、空间切换、显示器变化、唤醒、切换层级），以及每 30 秒，都会读系统窗口列表做一次自检，结果写进 `~/Library/Logs/MacWallpaper/desktop.log`（菜单栏图标 → 打开日志）。发现窗口丢失或被盖住时会自动重新排序，并记为一次"修复"。**长时间运行后累计修复次数应当是 0**；不为 0 的每一条都是要研究的问题。

## 已自动验证（2026-09-27，macOS 27.0，M2 Pro 内建屏）

| 项目 | 结果 |
|---|---|
| 三档层级（桌面层 / 桌面层+1 / 图标层−1）启动后的窗口顺序 | 全部正常：访达图标层 → 我们的窗口 → 系统壁纸 |
| 系统壁纸窗口 | 属于 `WindowManager`，位于桌面层−1 |
| 静置 CPU | 0.0% |
| 内存占用（footprint） | 61 MB，主要是 Retina 全屏的图层缓存 |

## 实测发现

- **全屏空间的背景板**：进入全屏应用的空间时，`WindowManager` 会在桌面层 +1 放一个盖满屏幕、不透明的窗口。它只在全屏空间出现，那时我们的窗口本来就被挡住，不影响。
- **编辑桌面小组件时，系统会把我们的窗口整个藏起来**（2026-09-28）：长按小组件进入编辑或拖动时，我们的窗口从屏幕列表里消失，系统自己的壁纸窗口（`WindowManager`，桌面层 −1）留在原处，于是露出原来的系统壁纸。桌面层、桌面层 +1、图标层 −1 三档都试过，结果一样，调层级解决不了。
  对策是"系统壁纸同步为当前画面"（`SystemWallpaperSync`）：内容换上去 3 秒后截一帧设为系统壁纸，切换空间后重新设置，退出时恢复原来的系统壁纸（kill 发出的 SIGTERM 也会正常退出并恢复）。原壁纸记在 UserDefaults 里，崩溃后再启动也能恢复。限制：系统壁纸按空间分别设置时，恢复只作用于当前空间。

## 通过标准

- 第 1–12 项在至少一档层级下全部符合期望；
- 连续使用一天，累计修复次数为 0，或者每一次修复都有明确原因和对策；
- 选定默认层级，并把理由记在本文件末尾。

## 2026-09-29：切换壁纸 / 改设置时的"黑一下"

用户反馈换壁纸、或者改壁纸设置（场景按属性重建）时会黑一下。原因是 `WallpaperController.reloadContent`
以前先把旧内容 `tearDown`、再把新内容的视图直接设成 `contentView`：新内容这时候还没有任何画面，
窗口露出来的是它那层黑底。这不是一闪而过——场景要现建渲染器（日志里 0.08–3.7 秒，Lucy 最慢），
视频要等解码出第一帧，网页要等页面画出来，黑的时间就是这么久。

现在换内容改成**交接**：

- 内容视图放在窗口 contentView 下面的一个容器里，新视图插进容器、放在旧视图**下面**
  （旧画面继续盖着它显示）；新视图在窗口里才拿得到 drawable，被挡住不影响它画第一帧；
- 新内容画出第一帧时（`DesktopContent.whenReady`）才撤掉旧视图、`tearDown` 旧内容、把新的接上；
- 三种内容各自报"能画了"：场景是 `SceneView` 成功呈现一帧之后（静态场景没有显示链路，
  拿不到 drawable 时会每 50 毫秒重试，最多 2 秒）；视频是 `AVPlayerLayer.isReadyForDisplay`
  （KVO）；网页是加载完成后等一次屏幕刷新（WKWebView 没有"第一帧画好了"的回调）；
- 兜底：`handoffTimeout`（默认 5 秒）内一直没准备好就先换上，免得旧画面一直占着；
  连着换好几张时，中间那些还没画出来的会直接拆掉，只认最后一张。
- 顺带一处：同步系统壁纸的截图原来是在换内容时排队、拍的是"当时的内容"，改成交接完成之后
  再按新内容排队（`scheduleSnapshot(for:content:)`），否则换完壁纸拍到的还是被换掉的那一张。

验证：

- `ContentHandoffTests`：新内容没画出来时旧内容不许拆、旧视图要留在屏幕上、新视图在下；
  准备好了才换；超时会兜底；连着换只留最后一张；另外验证**被挡住的 CAMetalLayer 照样拿得到
  drawable**（交接方案的前提）；
- `SceneContentFirstFrameTests`：最小场景包走完整条路（建渲染器 → 装进窗口 → 画第一帧 → 回调）；
- 换内容完成时日志里会写一行"显示器 N 换内容完成（新画面已就绪 / 等新画面超时…）"，
  长时间运行后这一行应该都是"新画面已就绪"。
