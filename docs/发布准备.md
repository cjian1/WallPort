# 发布准备（2026-10-04 更新：改成在 GitHub 上开源发布）

目标：源代码按 **MIT 许可证**公开在 GitHub 上，安装包放在仓库的 **Releases** 里供人下载。下面是现状、法律和用户层面的检查结果，以及**必须你本人做的事**（第四节）。
**法律和平台规则方面的判断不是法律意见，正式发布前最好找懂软件和游戏平台的律师看一遍。**

## 一、结论

1. **代码和打包这边已经齐了**：README（面向访客）、LICENSE（MIT）、CONTRIBUTING（不提交 WE 素材、不参考 GPL）、Issue 模板、
   检查更新改读 GitHub Releases、"反馈问题"指向 Issues、隐私政策和使用条款改成和 MIT / GitHub 一致、发布脚本和上传脚本。
2. **公开前清理过的东西**：测试里你的 Steam 登录名和本机路径换成了虚构的；旧的提交历史里还有它们和你的个人邮箱，
   所以**用全新历史发布**——本地分支 `github-release` 只有一个提交，作者是 GitHub 的匿名邮箱；codex / main 原样保留，不要推到 GitHub。
3. **最大的风险不在代码，在"依赖 Wallpaper Engine 和 Steam"这件事本身**（第二节）：开源以后谁都能看到实现，
   更要守住"不分发 WE 素材、不冒充官方、如实表明身份"。
4. **签名**：没有 Apple 开发者证书（每年 99 美元）也能发——很多 GitHub 上的 Mac 开源软件就是这样，用户第一次打开要去
   "系统设置 → 隐私与安全性"点"仍要打开"（README 里写了）。有证书的话 `release.sh` 会自动签名、公证，用户直接就能打开。

## 二、法律和平台

| 事项 | 现在的做法 | 还要你做的 |
|---|---|---|
| 和 WE / Steam / Valve 的关系 | README、欢迎页、登录框、"关于"窗口、使用条款里都写明"独立开发、没有关联、商标归权利人"；界面只说"兼容 Wallpaper Engine" | 查 "WallPort / 壁坞" 有没有人注册商标 |
| WE 自带素材 | **不随软件分发**（仓库、安装包里都没有）。用户登录后，壁坞用**用户自己的**账号从 Steam 下载他已拥有的 WE 安装包里的 `assets/`（约 85 MB，WE 更新时重新下载），只放在本机 `~/WallPort/Assets`；也可以手动导入；没有时用自己写的兼容素材 | 让律师看 WE 的用户协议是否允许在别的软件里用这些素材（和以前"手动导入"是同一个问题），或者联系 WE 开发者 |
| 创意工坊内容 | 用用户自己的账号下载（账号要拥有 WE）；壁坞不提供、不托管任何壁纸 | 同上 |
| 自己实现的 Steam 协议 | 如实表明身份：设备名 "WallPort (Mac)"、系统类型 macOS（不冒充 Steam 官方客户端或 Windows）；浏览页用默认的 User-Agent、不带 Cookie | Steam 订户协议对非官方客户端有限制：律师评估；README 和条款里已写明风险 |
| 用户的 Steam 密码 | 登录框用系统标准外观（不仿 Steam 的登录页），**扫码登录放在最前面作为推荐**；密码只发给 Steam、不保存；凭证加密存在 `~/WallPort/Data`，退出登录即删除；登录框底部写明这些和风险，并链到隐私政策、使用条款 | — |
| 成人内容 | 浏览创意工坊时，第一次勾"家长指导级 / 限制级"要确认年满 18 岁；没确认时只显示大众级；README 里也写了 | — |
| 隐私政策 / 使用条款 | `App/Legal/Privacy.html`、`Terms.html`（中英双语）随 App 打包，"帮助"菜单、欢迎页、登录框都能打开，README 里有摘要；按代码的实际行为写。使用条款写明源代码按 MIT 许可证、条款不限制 MIT 给的权利。发布者默认是仓库所属的 GitHub 用户名、联系方式默认是 Issues，**缺了就不让发**；适用法律可选（`GOVERNING_LAW`，不填时条款里不写这一句） | 最好让律师审一遍；定了适用法律就在发布时加上 |
| 第三方开源库和字体 | "关于"窗口附 glslang、SPIRV-Cross、zstd、LZMA 的许可证和兼容字体（OFL / Apache 2.0）的声明；字体许可证随字体打包 | — |
| GPL 代码 | 按产品计划不读、不参考 GPL / AGPL 实现（linux-wallpaperengine 等）；技术来源逐条记在 REFERENCES.md | 保持这个规则 |
| 数据和隐私法规 | 壁坞不向开发者发送任何数据（没有统计、广告、自动上报）；检查更新读的是 GitHub 的公开接口，开发者看不到请求 | 不用自建服务器，也就不涉及服务器日志和 ICP 备案 |
| 开源许可证 | MIT（`LICENSE`）；第三方代码和字体保留各自的许可证 | 版权人现在写的是 git 用户名 cjian1，想用真名就改 `LICENSE` 第 3 行 |
| 加密出口 | 只用系统的 HTTPS、RSA（Steam 登录）、AES-GCM（本机凭证），属于常见的大众市场加密；GitHub 上公开的开源代码一般不需要额外的出口申报 | 如果以后上 App Store / 面向特定国家，再按当地规定确认 |

`~/Library/Application Support`。现在保持 `~/WallPort`，隐私政策、卸载说明都按它写的。

看英文界面：先退出壁坞，再用 `open ~/WallPort/WallPort.app --args -AppleLanguages '(en)'` 打开（只对这一次生效）。

## 四、必须你本人做的事

**1. 建 GitHub 仓库并推上去**（全新历史，只推 `github-release` 这个分支）
- 在 GitHub 上新建一个**空的公开仓库**（不要勾"添加 README / LICENSE"），名字自己定，例如 `wallport`；
- 建议先在 GitHub 的 Settings → Emails 里打开 "Keep my email addresses private"，以后提交用 GitHub 给的匿名邮箱；
- 在仓库目录里运行（把用户名、仓库名换成你的）：

```
git remote add origin https://github.com/你的用户名/wallport.git
git push -u origin github-release:main
```

  以后在 GitHub 上的开发都基于这个分支；**不要把 codex / main 推上去**（旧历史里有你的 Steam 登录名和邮箱）。
- 推完以后在仓库 Settings 里：打开 Issues；Security → 打开 "Private vulnerability reporting"。

**2. 出安装包并发布**（在仓库目录里，`git switch github-release` 之后）
- 装 GitHub CLI 并登录一次：`brew install gh && gh auth login`；
- 打包（没有开发者证书时去掉 `SIGN_IDENTITY`、`NOTARY_PROFILE` 两项）：

```
BUNDLE_ID=io.github.你的用户名.wallport VERSION=1.0.0 \
SIGN_IDENTITY="Developer ID Application: 你的名字 (TEAMID)" NOTARY_PROFILE=wallport \
scripts/release.sh
```

- 发到 Releases：`VERSION=1.0.0 RELEASE_NOTES="第一个公开版本" scripts/publish-github.sh`（想先给少数人测就加 `PRERELEASE=1`）。
- 以后每次发布：`BUNDLE_ID` 不变，`VERSION` 递增（已经装了的壁坞按它判断有没有新版本）。

**3.（可选）Apple 开发者证书**：加入 Apple Developer Program（每年 99 美元），建 Developer ID Application 证书，再运行一次
`xcrun notarytool store-credentials wallport --apple-id <你的 Apple ID> --team-id <团队 ID>`。有了它用户打开时不会被拦。

**4. 法律**
- （可选）定下使用条款的适用法律，发布时加 `GOVERNING_LAW=…`；查商标 "WallPort / 壁坞"；
- 最好让律师看一下第二节的风险和两份条款；
- `LICENSE` 里的版权人想用真名的话改一下。

**5. 发布前测试**
- 至少一台没装过开发环境的 Mac：从 Releases 下载 → 拖进「应用程序」→ 第一次打开（没签名时按 README 的步骤"仍要打开"）→ 登录后看 WE 自带素材有没有自动下好；
- 扫码登录、账号密码登录、同步订阅、取消订阅；没导入 WE 素材、断网时的提示；英文系统下走一遍；
- 发第二个版本时，确认第一个版本能收到更新提示。

## 五、建议的顺序

1. 建仓库、推 `github-release`，先发一个 `PRERELEASE=1` 的预发布给少数人测；
2. 根据反馈修完，再发正式版（不带 `PRERELEASE`）；
3. 有条件时办 Apple 开发者证书，后面的版本都签名公证。
