# M6 验收：本地 329 个场景的「正常率」（2026-10-06）

## 一句话结论

**313 / 329（95.1%）正常**，超过 M6 的 85% 门槛。判定完全自动、可复现（`WallpaperTool acceptance`）。

但这个数字要连口径一起看：其中 312 个场景靠**一条写明的瞬态豁免**通过（`camerafade`，见下文），
如果连这条豁免也不认、要求逐项都实现，只有 **1 / 329** 完全干净——也就是说"画面正常"这件事，
现在的成立方式主要不是"什么都没漏"，而是"漏的东西写在名单上、且确认只影响开场一瞬间"。
这是本次验收最该被记住的一句话。

## 判定口径（可复现）

一个场景算「正常」，要同时满足（屏幕 1512×982，`WallpaperTool acceptance <目录> <素材目录> <输出目录>`）：

1. **能构建、能渲染** 0 / 1.5 / 6 / 12 秒四帧，没有抛错；
2. **没有未豁免的「暂不支持」和「问题」**——这一条是本次的重点，见下一节；
3. **该动的要动**：有"确定会随时间变"的内容（活粒子、木偶骨骼、精灵图、材质里读了 `g_Time`、
   摄像机对象动画、镜头抖动）时，四个时间点里至少有一对画面有差异（缩到 128×128 的平均差 > 0.05）；
4. **该跟鼠标的要跟**：打开 `general.cameraparallax`、而且有可见图层设了非 0 视差深度时，
   鼠标推向左上 / 右下两张画面要有差异（平均差 > 0.02）；
5. **取景不能明显错位**：按屏幕比例渲染的，和按画布比例渲染后取中间那一块，平均差 ≤ 6 且变化像素 ≤ 30%
   （作者把画布留得比内容大、取景故意平移的 `fillBox` 场景跳过）。

第 3、4、5 条的门槛是照着语料校准出来的：先用严格阈值跑了一遍，被大量**合理的**差异刷屏
（只处理点击的脚本不跟鼠标、"无流动"的水流本来就不动、文字防出界让两种比例下不完全一样），
收窄到只抓"确定该动 / 该跟却没反应"和"明显错位"之后才有意义。
项目里自带的 `preview.jpg` 相似度只当**软信号**记录，不作判定（预览图是作者自己框的局部，绝对值不可比）。

## 为什么原先的"体检"分数是虚高的

改动前 `WallpaperTool scene-report` 对同一批语料报的是：**329 个场景全部能构建，暂不支持只有 3 类
（脚本驱动字段 6、vortex_v2 1、eventspawn 1）**——看起来接近满分。

问题在于渲染器只报告它**自己知道自己跳过**的东西。有一批整场景特性是**解析层面就没读**，
既不报错、也不产生 `unsupported`，于是分数虚高。2026-10-06 直接在 329 个 `scene.json` 里普查：

| `general` 里的标记 | 场景数 | 改动前 | 改动后 |
|---|---|---|---|
| `camerafade`（开场淡入） | 328 | 零引用、静默忽略 | 仍不实现，**但会报出来**并列入豁免（见下） |
| `gravity*`（场景级重力） | 32（19 个有粒子） | 零引用、静默忽略 | 实现（粒子受力） |
| `cameraparallax*`（鼠标视差） | 16 | 零引用；对象 `parallaxDepth` 也没解析 | 实现（逐图层，含延迟平滑） |
| `camerashake*`（镜头抖动） | 3 | 零引用 | 实现（时间驱动的平滑噪声） |
| `zoom ≠ 1`（场景缩放） | 5 | 零引用 | 实现（绕画布中心缩放） |
| `hdr: true` 且开了泛光 | 2 | 按不处理，只写在文档里 | 仍不实现，**进入失分项** |

对应的代码改动：`WallpaperFormats/SceneDescription`（新解析 `general.zoom`、视差、抖动、重力、风，
对象新增 `parallaxDepth`、`brightness`）、`SceneRenderer`（场景级相机矩阵、逐图层视差、抖动、
图层亮度、`followsPointerPosition` / `animatesOverTime` 两个判定用的信号、新增
`SceneFeatureCoverage` 特性覆盖检查）、`ParticleSimulation`（场景级重力 / 风）、
`SceneState` / `SceneScript`（`thisLayer.parallaxDepth` 从占位变成真实可读写）。

**「覆盖检查」是这次真正的产出**：以后作者那边一出现没处理过的 `general` 键，
或某个"确认没实现、又可能改变画面"的图层字段（`perspective`、`castshadow`、`ledsource`…），
都会自动出现在报告里，而不是悄悄忽略。

关于量的口径：视差和抖动的**幅度** WE 没有公开单位，取的是保守的推断值
（`SceneRenderer.inferredParallaxScale = 0.05`、`inferredShakeScale = 0.01`，见 REFERENCES.md）。
方向上确定是对的（指针推左推右、画面跟着挪，逐像素可见），绝对幅度没有 WE 参照无法核对。

## 结果

| | 场景数 | 占比 |
|---|---|---|
| 正常（含豁免） | **313** | **95.1%** |
| └ 完全没有豁免、逐项干净 | 1 | 0.3% |
| 不正常 | 16 | 4.9% |

通过的那 313 个里，312 个带了豁免：**每一个都带"开场淡入"**（这条是全语料性的），其中 6 个另有
"脚本驱动的字段 + WE 同样报的 TypeError"，1 个另有"LED 联动"。也就是说 313 这个数字**几乎完全**由
"开场淡入算不算问题"这一个判断决定——第 2 节的白名单那一条一撤，通过率就掉到 0.3%。

### 逐轮数字（口径校准过程，留档）

| 轮次 | 通过率 | 说明 |
|---|---|---|
| 1 | 50.5% | 覆盖检查刚接上，暴露了 328 个 `camerafade`；"跟鼠标却不跟""有动画却不动"用最宽的口径判，假阳性极多 |
| 2 | 65.0% | 抖动 / 视差已实现；仍旧被"声明了 `g_PointerPosition` 的特效"和"静态特效链"刷屏 |
| 3 | 71.4% | 收窄到只认"确定会动"的内容 |
| 4 | **95.1%** | 视差按两个方向一起测（有的场景只有 Y 方向有深度）；只对"真开了视差且有非 0 深度"的场景判跟鼠标 |

（轮 1–3 的数字低，主要是判定口径还没校准，不代表代码一轮比一轮差。）

## 口径里的豁免（类别级，逐条给证据）

1. **开场淡入（`camerafade`）——328 个场景**。WE 加载场景时会从黑色淡进来，壁坞直接出画面。
   理由：差异只在开头一瞬间；`scene.json` 里**没有时长参数**（只有布尔），没有 WE 参照就无法复现它的时长和曲线；
   硬塞一个猜的淡入会改动全部 328 个场景的开场表现、且无法验证。**这是本次最大的已知偏差。**
2. **挂在 `visible` 上的拖动脚本（6 个场景）**。这几个场景把"拖动位置"的脚本挂在了图层的显隐字段上，
   **WE 自己也会报同样的错**（`Attempted to assign to readonly property`）、同样按静态值处理。
3. **LED 联动（`ledsource`，1 个场景）**：只驱动外接 RGB 设备，屏幕上没有对应像素，判它"画面不对"没有意义。

白名单是**类别级**的，不允许按场景逐个放行；新增类别要在这里补一条带证据的说明。

## 怎么复现

```bash
# 全部 329 个场景，屏幕 1512×982（默认）
.build/debug/WallpaperTool acceptance ~/WallPort/Workshop ~/WallPort/Assets /tmp/acceptance
# 输出：verdicts.json（逐场景）、summary.json、summary.md、images/（Everyone 分级的抽查图）

# 只要"暂不支持"汇总（不渲染），看覆盖检查抓到了什么
.build/debug/WallpaperTool scene-report ~/WallPort/Workshop ~/WallPort/Assets
```

`acceptance` 需要 GPU/Metal，得在沙箱外跑；渲染结果含壁纸作者的内容，**只能写在仓库外面**，
仓库里只放聚合数字和结论。退出码：通过率 ≥ 85% 为 0，否则为 1。
